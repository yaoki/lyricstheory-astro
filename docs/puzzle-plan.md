# 「作詞を解く」パズルの構想（2026-08-18）

Chat 側の検討からの派生。**まだ何も決めていない。**枠組みの側に素質があることの記録であって、作ると決めた記録ではない。

上位の設計原則は `docs/network-design-plan.md` の「ツールは判定せず、描くだけ」と `docs/sound-lookup-plan.md` の「最深部の地雷 — 判定装置への転落」にある。**この構想はその地雷の上を通る**ので、§3 を読まずに実装へ進まないこと。

---

## 1. なぜ素質があるのか

パズルの条件は二つだけである。**制約が明示されていること**と、**その中に自由が残っていること**。

子音ピボットはこの二つを満たす。軸が固定され、母音と意味は自由。**解が一つに定まらないのに、正誤ははっきりする。**折句やリポグラムが遊びとして成立してきたのと同じ構造である。

四操作（並行・倒置・展開・圧縮）はそのまま**手筋の一覧**になる。

## 2. 分析語と作詞語の二重命名が効く

`docs/theory-glossary.md`「連鎖ピボット」のガードレール1 が、分析の語と作詞の語を分けている。パズルではその区別がそのまま役に立つ。

| | 何を名指すか | パズルでの役 |
|:---|:---|:---|
| 分析の語（並行・倒置） | 結果 | **棋譜の記号** |
| 作詞の語（ピボット・連鎖ピボット） | 掴むもの | **手筋の名** |

「並行を作れ」は指示として成立しない（何を固定すればそうなるかを語っていない）。「カ行をピボットにせよ」は成立する。**出題は作詞語で書き、解答の記述は分析語で書く。**

## 3. 判定装置への転落をどう避けるか

**パズルには正誤がある。この理論は判定しないと明言している。**この二つは、何を正誤にするかを分ければ両立する。

- **制約の充足は機械的に判定してよい。** 「ここの頭子音は /k/ か」は表記を見れば決まる。事実の照合であって、価値判断ではない
- **良し悪しは判定しない。** 「この解答は韻として成立しているか」「うまいか」は出さない。想起が起きるかを判定するのは解いている本人である（`sound-lookup-plan.md` の装置A と同じ座らせ方）

**この線を越えた瞬間に、パズルは既存の韻判定ツールと同じものになる。**「あなたの解答は 78 点」を出した時点で、理論が「機械には判定できない」と言っている当の位置に機械が座る。

## 4. 出題の体裁は既にある

図はチャンクを並べて対応を示す形をしているので、**対応の印を消せばそのまま問題になる**（「並行形になるよう空欄を埋めよ」）。既存曲を使えば模範解答つきの問題ができる。

`figure` の4つの形のうち、出題に使えるのは次のように見込む（未検証）。

| 形 | 出題への向き |
|:---|:---|
| `single` | 呼応の弧を消し、色を伏せる。最も素直 |
| `consonant` | 子音記号を残して歌詞を伏せる＝「この子音の並びに乗る語を書け」。**作詞の課題に最も近い** |
| `pivot` | 既に伏せ字の図なので、軸だけ残せばよい |
| `pair` | 片方の行を伏せる。回帰反復の出題になる |
