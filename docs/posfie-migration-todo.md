# Posfie を「ネタ帳」としてブログ記事化する TODO（将来対応）

やおきさんの Posfie アカウント: https://posfie.com/@yaoki_dokidoki

**Posfie 記事を「そのまま移行」するのではなく、そこにある既存のまとめ（=ネタ・素材）から気になったテーマを拾い、ブログ記事としてリライト・再構成する**というワークフローの記録。

## 位置づけ

- Posfie は **公開ノート・アイデアの倉庫** として維持する（削除しない）
- ブログはそこから選ばれた素材を、**新たな批評として書き直す場**
- 移行ではなく、二次創作／派生創作に近い

## 資産の使い方

Posfie 側にある既存まとめは：

- 過去の X 上の考察・議論の蓄積
- どのネタがブクマ・反応を得たかの「実績」データ
- 引用したいツイートの URL 集

ブログ記事化する際は：

- Posfie に元ネタがあることを明記する必要はない（記事は独立した批評として立つ）
- 引用したいツイートは、その時点で X 側の埋め込みまたはテキスト引用で扱う
- 既存の Posfie 記事に手を加える必要はない（原ネタは Posfie にあり続ける）

## リライト時の記事化ワークフロー

**Posfie 記事にはタッチしない。**歌詞系のネタだけをブログに取り込む。歌詞系以外はどのラベルも付けず、Posfie に置きっぱなしで完全に放置する。

### ステップ0: 歌詞系ネタの抽出（**最初にやる**）

1. `https://posfie.com/@yaoki_dokidoki` を眺めて、**歌詞分析・作詞・音韻・音楽論に関するもの**だけを拾い出す
2. 出力先: `lyricstheory-astro/docs/posfie-lyrics-shortlist.md`（歌詞系だけの短いリスト）
   - URL / タイトル / 公開日 / 一言メモ（どの独自概念に接続できそうか等）
3. リスト内で優先順位を付ける
   - ブクマ数の多い順
   - 独自概念を含む順（子音ピボット・半シラブル化・宇多田カット・バップライティング・クローズドシラブル等）
   - 既存13記事とかぶらないもの順

### ステップ1以降: 記事化

1. **ネタ選定**: ショートリストから1つピック
2. **新規記事として起稿**: `src/content/blog/YYYY/<slug>.mdx` を新規作成
3. **Posfie の内容は下敷きに留める**: 使うのは「発想の起点」であって、文章の逐語コピーではない
4. **必要ならツイート引用**: `<XPost url="..." />` のようなコンポーネントを後日必要になったら用意
5. **frontmatter は通常通り**: title / description / pubDate / categories / concepts

## Phase 3-4 で確立した資産のうち流用可能なもの

- Content Collections `blog` schema — カテゴリ・概念タグはそのまま使える
- `<LyricQuote>` `<EmbedIframe>` などの MDX コンポーネント
- schema.org Article / OGP / TOC 自動生成
- **逐語保存原則は適用しない**（リライトなので原型を保つ必要がない）

## 想定される追加コンポーネント（必要になったら作る、MVP 原則）

- `<XPost>` / `<Tweet>`: X ツイートの静的引用（削除・非公開化しても本文が残るように、text + author + URL の3点セット）
- `<PosfieCite>`: 元ネタとなった Posfie ページへの参照リンク（任意、書きたい記事があるときだけ）

## 注意点

- **Posfie 側 URL からブログへのリダイレクトは行わない**: Posfie 記事は Posfie に残るし、ブログ記事は別物として立つ
- X ツイート引用は本人ツイートなら無問題。他人ツイート引用は Posfie でも同じ判断が既にされているのでその引き継ぎ
- Posfie 記事の数に対して、ブログ化するのは一部（全部やる必要はない、選定が重要）
