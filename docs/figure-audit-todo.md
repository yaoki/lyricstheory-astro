# 図の点検で残った課題（2026-08-04）

elements 全55枚（figure を持つ49枚）を5体のエージェントで点検した結果のうち、**やおきさんの裁定が要るもの**と**道具が足りないもの**。描画側の破れ4件とカードの型の取り違え5枚は同日に修正・デプロイ済み。

判定の手順は `.claude/agents/figure-critic.md` にある。**縮小版（`sips -Z 400`）から先に見ること。**原寸で美しくてもタイムラインでは 1/3 に縮む。

## A. 図と本文が違うことを言っている（3枚）

図が正しいのか本文が正しいのか、やおきさんにしか決められない。

- **`wekapipo-fixed-vowel-a`** — 本文は「ア母音が**七音**続く」「あ・ら・あ・ら・あ・ら・な」。図は `highlight: [0,1,2,3,5]` で**8モーラ**を着色し、間に「み」が挟まって連続していない。「た」を落として本文に合わせるか、本文を「七音続き、みを挟んでもう一音」に直すか
- **`pretender-cv-repetition-a-prime`** — タイトルが「（い／そ／り）」と3つ約束するのに、図の「そ」は**灰色で描かれている**（＝図が「そは呼応していない」と主張している）。`units` は7枠で1枠余っており、上限8のせいではない
- **`pretender-cv-repetition-a`** — タイトルが「（と／そ／り）」と言うが、図にあるのは `と…と` の1組だけ。1行目が9枠あり、名指しされた「り」が上限8で切り落とされている。**こちらは上限が原因**なので、タイトルを図の範囲まで狭めるか、カードを割るか

## B. 文脈が本文の引用範囲で終わっている（4枚）

いずれも `units` に空きがあり、**上限8のせいではない**。カード本文の `<LyricQuote>` が呼応部分の片側で終わっているため、図にも文脈が入らない。歌詞の続きが repo に無いので Claude 側では伸ばせない（推測で足すと捏造になる）。

| slug | 使用枠 | 欠けている側 |
|---|---|---|
| `kuchibue-consecutive-vowel-a3-first-chorus` | 5/8 | 右 |
| `kuchibue-consecutive-vowel-o4-first-verse` | 5/8 | 右 |
| `kuchibue-consecutive-vowel-e3-first-chorus` | 6/8 | 右 |
| `kuchibue-consecutive-vowel-o6-bridge` | 7/8 | 左 |

**やること**: 本文の引用範囲を1〜3音伸ばす。その後 `npm run figure -- --card <slug> …` で図を作り直せば自動で反映される。

なお `kuchibue-aba-voicing-ka-ga` / `-a4-first-chorus` / `-a4-last-chorus` は8枠を使い切っているが左に偏っており、左を1枠削れば右に文脈を1つ置ける（配分の問題）。

## C. 上限8では観察が収まらない（1枚）

- **`kuchibue-consecutive-vowel-i3-a6-second-chorus`** — 観察に必要な枠は イ3 + っ + ア6 = **10枠**。文脈ゼロでも上限に入らないため「かった」を3モーラ1枠に畳んでいる。その結果、①タイトルの「ア6連続」に対し着色が7つに見える、②畳みを示す括りが縮小版で 1px 未満、③8枠すべてが着色されて地と図の区別が消える、という3つが同時に起きている。
  - 同じシリーズの `a4-first-chorus` / `a4-last-chorus` は「っ」を dim に落としているのに、このカードだけアクセント色に入れており、**シリーズ内で /Q/ の扱いが割れている**
  - **やること**: カードを2枚（イ3連続 / ア6連続）に割る。割れば各々5〜6枠で済み文脈も入る。1枚に残すなら図に載せる連続を片方だけにする

## D. 道具が足りない（実装が要る）

### D-1. pair の長い行〔2026-08-04 解決済み〕

**`wraps` を実装した。**やおきさんの指示「2小節ごとに改行してみる」による。

```yaml
wraps: [[17], [17, 31]]   # 各行を折り返す位置（音の index）
```

`kuchibue-return-repetition-chorus` は 17px → 約40px になった。音数は1つも減らしていないので「展開では切り詰めない」と両立する。

- 段が増えたぶんは字を小さくするが、使える縦の範囲（`PAIR.topLimit` 〜 `bottomLimit`）から逆算するので、何段でもタイトルに被らない
- ラベルの下限は段数で割る（ラベルは各行の先頭の段にしか付かないので、段が増えれば間隔は自然に開く）
- `aligned` では使えない（列の突き合わせが成り立たないため、schema が止める）

**残っている懸念**: `pair.ts` にはなお字の下限が無い。`wraps` を書き忘れた長いカードは黙って細るので、下限を設けて下回るならビルドを止めるほうが安全。

### D-2. `figure.ts` に pair の生成経路が無い

既存の pair カード6枚はすべて YAML 手書き。`--card` で自動化できない。さらに `pair.ts` は1枠1文字前提なので、2モーラを1枠に畳むと隣と重なる（2026-08-04 に「ために」で実測）。

これが解けないと **`there-will-be-love-there-return-repetition`** に図を付けられない（第一候補が pair のため）。

### D-3. 3箇所以上を並置する形が無い

規約は「**行数＝図に載せる箇所の数**」と言うのに、実装は single(1) と pair(2) しかない。

- **`kuchibue-consecutive-as-special-case`** — 3箇所を束ねるメタカード。図を持てない
- **`ame-nochi-hare-syllabification`** — 現在 `kind: consonant` を流用しているが、34音のうち記号が付くのは3つだけで**91%が薄色**になる。consonant は「交替が起きている範囲を浮かび上がらせる」機構なので、浮かび上がらせる範囲が存在しない。テンプレートの取り違え

### D-4. pivot が軸を1本しか持てない

やおきさんの仮説（2026-08-04）：**「雨のち晴れ」のタ行とカ行を1枚にすると、リズミカルな構造が見えてくるかもしれない**。

実際に数えると2行目は `k k t k k t k t` で、**仮説は支持されそう**（1軸ずつ見ていては見えない）。ところが `axis` が単数・点も1色なので、2軸を重ねるとどちらの軸か区別できない。

`kind: consonant` は使えない。この型は「2つの子音が**続けて**交替する範囲」を取るもので、雨のち晴れは t と k のあいだに必ず別の子音が挟まる（ん・ぱ・し・る・ら・ぼ・ひ・り）。連続する範囲は「がういて」の1箇所だけ。

**やること**: `--pivot2` 相当を足し、軸ごとに色を変える。

### D-5. `correspondences` が塊を宣言できない

- **`esora-contraction-sutameni`** — ラベルは `ABC` / `AC` で3要素を宣言するのに、図は4色を塗る（C にあたる「ために」が3色に割れている）。読者が A・B・C を色に対応づけようとすると必ず失敗する
- 型が `[number, number][]` で1モーラ↔1モーラしか書けない。`pair.ts` が単元素ブロックに包むため、手書きでは塊を作れない。塊を作れるのは自動抽出の経路だけ
- **やること**: `[number[], number[]][]` も受けられるように広げる（`figure.ts` / `content.config.ts` / `pair.ts`）。そのうえで `[[1],[1]]` / `[[5,6,7],[2,3,4]]` と書けばラベルと色が一致する

### D-6. consonant の記号が縮小で消える

- **`there-will-be-love-there-tk-alternation`** — 記号が 22.1px、SNS 1/3 で 7.4px となり `t` `k` `Φ` の判別がつかない。規約が「抽象（記号）と実音（歌詞）の対応こそが図の本体」と定めている、その本体の半分が消える
- `CONSONANT.markRatio`（0.62）を 0.75 程度まで上げると 26.7px になる。ただし23列という制約は残る
